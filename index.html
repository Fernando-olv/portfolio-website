AI Code Auditor

MVP

Problem
Pull-request review is easy to spam with noisy bot comments and hard to make consistent. The goal was a service that reviews a PR once per push, combining deterministic checks with a second-pass model review.
Engineering
A FastAPI service accepts signed GitHub webhooks, acknowledges quickly, analyzes the unified diff with a rule engine plus an LLM adapter, scores findings, optionally persists the run, and posts a single idempotent PR comment.
Technical decisions
Ports-and-adapters boundary for LLM and storage vendors; HMAC verification of X-Hub-Signature-256; HTTP 202 dispatch; a hidden head-SHA marker so comments update instead of stacking; Cloud Run deploy path with Secret Manager.
What it demonstrates
API design, webhook security, service boundaries, structured logging, and testable backend architecture. Shipped as an MVP with unit tests and documented limitations—not as a finished product claim.

Store Backend Service

Problem
Build a cloud-oriented store backend with clear auth, product, and order boundaries—runnable locally with Docker and described as infrastructure, not only as application code.
Engineering
FastAPI exposes register/login, product CRUD, and JWT-protected orders. Firestore is used for persistence (emulator locally, managed in GCP). Docker Compose and Make targets cover health checks and a production-like local run.
Technical decisions
JWT for authenticated order flows; environment-driven secrets; Terraform for GCP infrastructure; local/prod Docker paths so the same service can be exercised without a live cloud account.
What it demonstrates
REST API design, authentication, data modeling, Docker workflows, and infrastructure-as-code for a small backend service.

SIEM Homelab with Elastic Stack

Problem
Security monitoring is hard to learn as disconnected tools. The lab needed a small, reproducible pipeline that shows a full event lifecycle: activity, collection, indexing, and investigation.
Engineering
Docker Compose wires an Ubuntu endpoint, Filebeat, Elasticsearch, Kibana, and an attacker container used to generate authentication events such as failed SSH logins. Logs move from /var/log/auth.log into a Filebeat index that can be queried in Kibana.
Technical decisions
Intentionally minimal architecture: endpoint → forwarder → SIEM. Shared volumes for log shipping; Elastic security features left off because this is a lab, not a production cluster. The value is the integration path, not a dashboards screenshot.
What it demonstrates
Systems integration, observability, Docker, Linux, log ingestion, and defensive security as engineering—not as a hacking showcase.

Engineering philosophy

Build → Observe → Break → Improve

Software engineering is iterative. Clear boundaries are not enough if you cannot see how a system fails, or refuse to change it afterward. Security belongs here: it is how you design for misuse, not a separate personality.

01

Build

Give services explicit boundaries, boring APIs, and data models that are hard to misuse.

02

Observe

Logs, metrics, and traces are part of the design. If you cannot see it, you cannot operate it.

03

Break

Study failure modes and attacker-shaped traffic so the next revision is informed, not hopeful.

04

Improve

Tighten resilience, reduce attack surface, and keep the mental model small enough to teach.
